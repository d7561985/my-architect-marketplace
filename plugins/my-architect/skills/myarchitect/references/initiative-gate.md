## Приложение A · Свод правил формирования инициатив (v0.9)

> Статус: рабочая версия, ожидает финального апрува владельца. Правила — подсказки автору, не бюрократическая форма. Область: технические трансформации и энейблеры бизнес-задач.

### Гейт — 7 вопросов перед оформлением инициативы

1. **Что было → что станет?** Исходное состояние с фактом (числом, если есть); целевое — проверяемое и сформулированное глазами бизнеса.
   **Система координат обязательна.** Дельта считается против мира, где параллельные работы уже идут своим ходом. Нельзя приписывать инициативе ценность идущей рядом трансформации («станет быстро» — потому что переходим на новую платформу, а не потому что сделали эту задачу). Если инициатива — энейблер внутри большой трансформации, её «станет» — это то, что без неё в трансформации **не заработает**, а не то, что трансформация даёт сама.
2. **Кто потребитель, поимённо?** Таблица: фича/KR → чем блокируется сейчас → что сможет после → чья это цель. Нет ни одного поимённого потребителя — не делаем.
3. **Что уже работает и не трогаем?** Ценность считается на дельту, не на всю систему. Это же — готовый ответ на «и так работает».
4. **Что теряем, пока ждём?** Цена промедления в 1–2 предложениях + профиль срочности: «линейно капает» / «до даты X — ноль, после — резко» / «сгорает». Честное «ничего» → «не сейчас» + триггер пересмотра.
5. **Что будет, если не делать?** Опция 0 как измеримый тренд на 6–12 месяцев + честный do-minimum (самая дешёвая альтернатива и почему её недостаточно). Опция 0 может выиграть — это легитимный исход.
6. **Сколько готовы потратить и что в остатке?** Аппетит вместо оценки. «Готово на 95%» без поимённого перечня остатка и его цены — не аргумент.
7. **Обратимо ли?** Двусторонняя дверь → пилот без лишних согласований. Односторонняя → полный расклад + kill-критерий вида «состояние + дата».

### Правила текста

- **SCQA первым абзацем:** ситуация → осложнение → вопрос → ответ. Читатель за один абзац понимает, зачем читать дальше.
- **Стоп-лист + тест переворачиваемости:** «опора», «фундамент», «полноценный», «единый», «гибкость», «разблокирует» без конкретного продолжения, unlock/enable/foundation. Тест: если отрицание фразы бессмысленно — фраза пустая.
- **Пункт ценности не заканчивается артефактом:** «Сделаем X → актор сможет Y → увидим по Z».
- **Модальность ЦЕЛЬ/СЕЙЧАС:** целевые числа и состояния всегда помечены как цель.
- **Эпик читается без глоссария**; термины единые по всему пакету документов.

### Процесс

- **Две корзины:** работа ≤ пары недель и без изменения межсервисных контрактов — себестоимость команды, наверх не выносится и гейт не проходит.
- **Спина → апрув → текст:** сначала скелет (ответ на каждый вопрос гейта одним предложением), апрув владельца, потом полный текст.
- **Один владелец у каждого текста:** эпик = зачем + границы; задача = что + как; трекер = заголовок + критерии + ссылка. Ничего не дублируется.
