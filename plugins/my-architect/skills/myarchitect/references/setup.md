# Setup — проект Архитектора для текущего репозитория

Результат: пользователь выбирает или создаёт проект, агент проверяет его и сохраняет точный ID локально. Пользователь не должен искать `pid` вручную. Это локальная связь репозитория с проектом, не регистрация Git URL на сервере.

**До первого общего project GET:** для любого впервые проверяемого/неизвестного legacy-проекта сначала безопасный discovery. Разреши точный pid ниже, затем используй поддерживаемый catalog reader либо [safe audit](product-migration.md); обычный `get_project_context` на старом backend может ремонтировать storage. Init/doctor/sync не являются безопасной проверкой. Успешный пустой каталог — повод проверить источники, а ошибка чтения не считается отсутствием структуры. По [границе маршрутов](../SKILL.md#граница-обычной-записи-и-adoption) отдели новую обычную дельту от унаследованных несопоставленных записей: для последних агент сам выполняет [adoption](migration-adoption.md) в scope задачи; отдельная команда migrate не обязательна. Это не разрешение на произвольную миграцию всего проекта или запись при read-only поручении.

## 1. Проверить существующую связь

Прочитай local `AGENTS.md`/`CLAUDE.md`, если они есть, и существующий `.architect/traceability.json` (также путь из маркера `my-architect:traceability`). Сопоставь все явно указанные для этого репозитория ID: `my_architect pid: "<id>"`, `projectId`, явное `my_architect MCP project <id>`/`Canonical source` и выбор пользователя в текущем разговоре. Упоминание имени продукта или соседнего репозитория связью не является.

- ID согласованы → используй связь без нового вопроса. Сохраняй пробелы, регистр и весь ID; не делай slug из имени или пути репозитория.
- ID конфликтуют или значение неоднозначно → покажи источники и уточни правильный проект до зависимых записей. Сохрани существующий индекс и конфигурацию.
- Связи нет → перейди к выбору. Отсутствие traceability-конфига само по себе не доказывает, что проект не создан.

## 2. Выбрать существующий или создать новый

Вызови `list_projects({})`. Ошибка доступа/сети — проблема подключения, а не ноль проектов: сообщи точную ошибку и способ восстановить соединение по фактической конфигурации. Если список не удалось получить, не создавай проект и не записывай привязку до восстановления доступа.

После успешного ответа предложи понятный выбор, например:

> Для этого репозитория ещё не выбран проект Архитектора. Какой существующий проект использовать, или создать новый?

Покажи реальные названия из ответа. При нуле проектов предложи создание и запроси недостающие имя и структуру. При любом непустом списке оставь возможность создать отдельный проект. Единственный результат и сортировка по недавнему обновлению не устанавливают связь с репозиторием. Если пользователь откладывает выбор, оставь связь ненастроенной и укажи `/my-architect:init` для продолжения.

Пользователь уже выбрал проект или явно поручил создание → используй это решение без повторного разрешения. Для существующего проекта возьми точное поле `path` из результата `list_projects` как `pid`; похожее название не является ID. При неоднозначном совпадении уточни выбор.

Для создания согласуй имя и `preset`: `simple` — простая иерархия, `agile` — agile-структура, `safe` — SAFe. Выбор влияет на уровни проекта; не назначай его молча. Параметр `custom` тоже существует, но текущий `scaffold_project` не принимает произвольные `levelNames`: он создаёт уровни по умолчанию. Если нужна собственная структура, сначала объясни это ограничение и уточни поддержанный способ её настройки; не обещай передать произвольные уровни через этот вызов.

Вызови существующий `scaffold_project` с согласованными полями и **`withSampleContent: false`**. Используй точный `project_id` из успешного ответа. Ошибка создания не даёт ID; не объявляй успех и не повторяй создание вслепую после неясного сетевого результата — сначала проверь список, чтобы не создать дубликат.

## 3. Проверить и сохранить

Проверь выбранный/созданный ID фактическим безопасным `get_product_catalog({pid})` или `get_migration_audit({pid})` и точной привязкой ответа. Имя tool не доказывает поддержку удалённого сервера. Для legacy-содержимого нужен safe audit; общий `get_project_context` не обязательный шаг проверки связи. Если безопасные readers недоступны, сохрани выбор и точное ограничение без claim полной проверки/repair fallback. Ошибка доступа или отсутствие проекта требуют исправления доступа/выбора; не переключай репозиторий на другой проект автоматически.

После успешной проверки сохрани связь в репозитории:

- Когда реальные команды тестов и CI установлены, выполни installer из `/my-architect:init`. Он записывает `projectId` в `.architect/traceability.json` и блок с `my_architect pid: "<id>"` в `CLAUDE.md`.
- Если команды пока требуют уточнения, сохрани подтверждённый ID отдельной явной строкой в `CLAUDE.md`, сохранив остальной текст. Не создавай конфиг с выдуманными командами. При последующей установке приведи строку привязки к одному блоку installer без изменения ID и пользовательских инструкций.

Перечитай записанные файлы: ID должны совпадать. Существующий installer не переключает projectId и не перезаписывает пользовательский runtime/config. Конфликт или намеренная смена проекта требует отдельного решения о существующем индексе; не удаляй требования ради новой связи.

## 4. Продолжить настройку и сообщить результат

Когда доступен `get_epic_flow`, выполни read-only remote check по [epic-flow.md](epic-flow.md). Успешный compact response подтверждает только поддержанное чтение; 404/ошибка не являются пустым registry. Самостоятельная настройка связи/traceability при init не означает разрешения enqueue всю историю, claim чужую работу или принять policy. Если текущая порученная работа требует ограниченной adoption после safe discovery, продолжи её по migration-adoption reference в этом scope. Современные task tools на несовместимом flow backend могут вернуть capability error; не обходи его legacy writes, продолжай независимые доступные шаги.

Проверь каталог по [product-catalog.md](product-catalog.md): найди доступный `get_product_catalog`, выполни удалённое чтение для проверенного `pid` и сообщи его реальный результат. Сохрани `remoteSchemaVersion` отдельно от нормализованного `catalog.schemaVersion`: удалённый v1 не подтверждает запись v2, поэтому такие записи остановлены. Успех с revision 0 означает ещё не созданный каталог; отсутствие инструмента, 404, сеть/доступ и неподдерживаемый формат не означают пустой реестр. Init не превращает всё дерево в каталог и не утверждает карту по одному успешному GET. При унаследованных структурных пробелах в порученной задаче используй [inventory/dry run](product-migration.md) и [adoption](migration-adoption.md); при недоступной capability зависимые сопоставления остаются pending, без замены package каталоговым CAS. Независимая настройка прослеживаемости продолжается.

Выполни остальные шаги `/my-architect:init`: синк реальных данных → постоянные тесты → CI → проверка мутациями. Новый проект может быть пустым: привязка уже сохранена, но прослеживаемость ещё не готова. Не создавай фиктивные требования/issues, sample content или blanket waivers ради зелёного гейта.

В ответе отдельно укажи выбранный проект и сохранённые пути, поддержку/состояние каталога, что проверено в тестах/CI и что осталось. «Связь сохранена» не равно «прослеживаемость полностью настроена» или «проект мигрирован». В новой сессии агент читает сохранённую связь, а не повторяет выбор по списку проектов; доступность каталога проверяет свежим чтением.

## 5. Переносимый workflow upgrade

В разрешённой работе применяй [work-visibility.md](work-visibility.md): проверь `.architect/agent-workflow.json`, адресно сверь действующие owner instructions и старые generated правила в `AGENTS.md`/`CLAUDE.md`, сохрани source/hash receipt после сверки. Это общий путь Claude/Codex независимо от поддержки hooks. Не принимай недостающий receipt за новое разрешение на запись и не запускай общий аудит на каждом resume. Принятая реализация включает самостоятельные enqueue/claim в её scope; setup/read-only сам по себе не активирует backlog.
