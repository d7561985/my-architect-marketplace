# Рецепт · Аудит кодовой базы целиком

Предусловие: задача — repo-scale понимание («проведи аудит», «пойми кодовую базу», "map this codebase"), НЕ правка известных файлов.

## Шаги

0. **Сверься с [code-graph.md](code-graph.md) — граф есть или нет.** Свежий граф: сперва прочитай `graphify-out/GRAPH_REPORT.md` (god-ноды, communities, surprising connections — сводка уже готова), партиционирование и карта модулей — оттуда. Отсутствие графа — повод предложить владельцу bootstrap (один раз), а не молчаливый пропуск.
1. **Партиционируй по структуре, не по размеру** (`Bash`): `git ls-files | awk -F/ '{print ($2=="" ? $1 : $1"/"$2)}' | sort | uniq -c | sort -rn` — модули верхнего уровня; `du -sh` по крупным. Итог — список модулей с весами.
2. **Один агент на модуль** через канонический скрипт (chunks = директории модулей; агент читает ТОЛЬКО внутри своего модуля). Schema: `{module, purpose, key_apis[], risks[], facts[]}` — каждый facts-элемент несёт путь к файлу.
3. **Multi-modal sweep для тщательного аудита** — 2–3 линзы отдельными map-проходами, каждая слепа к другим: по-структуре (что где лежит), по-зависимостям (кто кого импортирует: grep import/require), по-тестам (что покрыто). Одна линза не находит всего.
4. **Loop-until-dry:** держи `seen`-набор; стоп после 2 подряд раундов без нового.
5. **Completeness-critic:** финальный агент спрашивает «чего не хватает — модуль не посещён, утверждение без пути, линза не прогнана?» Его находки = следующий раунд.
6. **Синтез:** карта репо / аудит; каждое утверждение сохраняет путь-доказательство.
