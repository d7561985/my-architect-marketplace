# Рецепт · Code-graph: персистентный граф кода (Graphify-класс)

Модификатор для repo-audit / requirements-mining и Workflow D скила myarchitect — и самостоятельный вход для impact-вопросов по символам («кто зовёт X», «что сломается при смене сигнатуры»): если в репозитории живёт локальный индекс кода — спрашивай сперва его; grep-скоупинг превращается в запрос за секунды, и знание репо переиспользуется между сессиями. Референс-реализация: [Graphify](https://github.com/safishamsi/graphify) — код парсится tree-sitter'ом локально (без API-вызовов), индекс лежит в `graphify-out/graph.json`, свежесть поддерживают git-хуки и `graphify . --update`.

## Presence + freshness (первым делом, дёшево)

```bash
[ -f graphify-out/graph.json ] && echo present || echo absent
# свежесть: индекс не старше последнего коммита
G=$(stat -c %Y graphify-out/graph.json 2>/dev/null || stat -f %m graphify-out/graph.json 2>/dev/null)
H=$(git log -1 --format=%ct)
[ "$G" -ge "$H" ] && echo fresh || echo STALE
```

- `absent` → см. «Bootstrap по согласию» ниже: на big-corpus задаче предложи владельцу собрать граф (один раз); отказ → базовые рецепты, без деградации.
- `fresh` → граф — первый источник кандидатов.
- `STALE` → скажи об этом явно и предложи владельцу `graphify . --update`; кандидатов из протухшего графа помечай «по устаревшему индексу» и не делай по ним выводов без verify по текущим файлам. Если git-хук не установлен — один раз предложи `graphify hook install`, чтобы STALE не повторялся каждую сессию.

## Карта запросов

| Вопрос | Запрос |
|---|---|
| «что связывает X и Y», обзор подсистемы | `/graphify query "…"` |
| путь / цепочка вызовов между символами | `/graphify path "A" "B"` |
| «что такое X, кто его использует» | `/graphify explain "X"` |
| impact: «кто зовёт X», «что сломается при смене X» | `graphify affected "X"` → verify по задетым файлам |
| сводка по репо: god-ноды, communities, неожиданные связи, suggested questions | прочитай `graphify-out/GRAPH_REPORT.md` — она уже готова, не собирай её запросами |
| структурный доступ (поднят MCP-сервер Graphify) | `query_graph`, `get_node`, `get_neighbors`, `shortest_path` |

## Правило честности (не обсуждается)

Граф — **навигация и кандидаты, НЕ источник фактов**. Ответ графа говорит, КУДА смотреть; фактом становится только подтверждённое живым файлом: контракт `{claim, evidence_path, confidence}` и verify-pass (requirements-mining, шаг 4) действуют без изменений — граф заменяет только шаг скоупинга. Причина: индекс отстаёт от кода между пересборками; решения принимаются по коду, не по индексу.

**Verify — экономно, регионами.** Кандидат графа приходит с `путь:строка` — читай регион вокруг неё (±30 строк через offset/limit или `sed -n`), не файл целиком; целый файл — только когда региона не хватило. Именно этот шаг конвертирует пользу графа в экономию токенов: без него verify съедает всё, что граф сэкономил на скоупинге.

## Интеграция

- **repo-audit, шаг 0:** партиционирование и карта модулей — из графа (communities, hub-ноды); fan-out дальше как обычно, вопросы агентам уточнены кандидатами.
- **requirements-mining, шаг 0:** скоупинг «какие подсистемы ответят на вопрос гейта» — запросом к графу вместо `git ls-files` + `grep -l`.
- **Workflow D (myarchitect):** взяв ноду в работу при свежем графе — сперва связи затрагиваемых символов у графа, потом точечный verify по файлам; в ноду/доку попадает только verified.

## Bootstrap по согласию (графа нет, а задача big-corpus)

Молча ставить инструмент по-прежнему НЕЛЬЗЯ — но и молча страдать grep'ом не надо. Графа нет, а задача big-corpus класса (аудит репо, requirements-mining, работа по крупному репо)? Предложи владельцу **один раз за сессию**, с честной ценой и выгодой:

> Могу поставить Graphify и собрать граф кода: `uv tool install graphifyy` (или `pipx install graphifyy` — пакет с двумя «y») + `graphify update .` — локально, code-only без API-ключей, сборка за секунды; заодно git-хук `graphify hook install` (свежесть + merge-driver). Каталог `graphify-out/`: команде README рекомендует **коммитить** (общая карта для всех, конфликты graph.json решает merge-driver; в .gitignore — только `cost.json`/`cache/`), соло можно и весь каталог в .gitignore. Дальше кандидаты по коду будут приходить из графа мгновенно, знание репо переиспользуется между сессиями. Ставим?

- **«Да»** → выполни всё из предложения: `uv tool install graphifyy` (фолбэк: `pipx install graphifyy`), `graphify update <repo>`, хук, согласованный вариант для `graphify-out/` (коммитить или .gitignore). Продолжай текущую задачу graph-first.
- **«Нет»** → базовые рецепты без деградации; в этой сессии больше не предлагай.
- Предложение — развилка, не гейт: саму задачу не блокируй ожиданием ответа дольше одного вопроса.
- Бонус каждой сборки: `graphify-out/graph.html` — интерактивная визуализация графа для браузера (владельцу бывает полезнее твоего текстового ответа).

## Фолбэк

Графа нет и владелец отказался (или спросить некого — headless) → базовые рецепты, без деградации и без повторных предложений.
